\section{The frontier is the non-terminal results}
\label{sec:map}

A \emph{question} is
$q = (\textit{language}, p, \textit{observable}, \textit{mode},
\textit{bound})$ with mode existential or universal and bound
$k$ or $\infty$; a \emph{benchmark} $B$ is a pinned finite set of
questions with recorded provenance --- sha256 per program, labels
where they exist --- pinned so that ``the benchmark'' names the same
set at every iteration.

\paragraph{The order}
Results for a question are ordered by the key
$(\textit{level}, \textit{bound}, \textit{grade})$,
lexicographically:
\[
\underbrace{\textit{partial}}_{\text{level } 0}
\;<\;
\underbrace{\textit{all}(k) \text{ below the ask}}_{\text{level } 1}
\;<\;
\underbrace{\textit{terminal}}_{\text{level } 2}
\]
where \emph{terminal} is a replayed witness or a universal claim
covering the asked bound; within a level, higher bound wins, then
higher grade. Cost is deliberately not in the key: it is recorded
and reported, never ranked, so a cheaper result never displaces a
stronger one.

\paragraph{The frontier}
The \emph{frontier of $B$} is the set of questions whose best result
is not terminal --- each carrying the route that produced its best
result and that result's progress evidence, which is exactly ``the
non-terminating results with the route to get there.'' There is no
second ledger: what the previous design kept as books, boards, and
demand records \emph{is} the frontier's partial results, read as
prose. \emph{Expanding the frontier} means strictly improving some
question's best result --- level, bound, or grade, never cost.

\paragraph{Monotonicity for free}
The registry and the per-benchmark log are append-only, and
best-per-question is a fold over the log. Exploration is therefore
monotone \emph{by construction}: appending records can only improve
the best (\textsf{best\_mono}), and a question once terminal stays
terminal (\textsf{terminal\_ratchet}) --- both mechanized in the
kernel's own Lean development (\cref{sec:proofs}). What the previous
design carried as a facilitation theorem over a filtration model is
now a property of a data structure. The exit deliverables inherit
this: the frontier report is a pure function of the log and
regenerates byte-identically, so pulling the plug mid-run loses
nothing and forges nothing.
